Scripting API

GPEC's pipeline is normally driven from a gpec.toml deck through GeneralizedPerturbedEquilibrium.main. The scripting API exposes the same stages as ordinary Julia functions, so a run can be built, parameterized and looped over in a script without writing a deck.

using GeneralizedPerturbedEquilibrium

eq  = PlasmaEquilibrium("input.geqdsk"; jac_type="hamada")
ffs = solve(eq, Riccati(); nn=1, delta_mlow=8, delta_mhigh=8, vac_flag=true)
rmp = RMPField("coils.dat")
resp = plasma_response(ffs)
pe   = perturbed_equilibrium(resp, rmp)

solve(eq, alg; kwargs...) is sugar for the canonical problem form: a ForceBalanceProblem names WHAT is being solved (the perturbed-plasma Euler-Lagrange system posed on this equilibrium, with this mode range, wall and closure) and the integrator names HOW. A PlasmaEquilibrium hosts many possible problems; the problem type keeps solve unambiguous as other problem classes appear.

prob = ForceBalanceProblem(eq; nn=1, delta_mlow=8, delta_mhigh=8, vac_flag=true)
ffs  = solve(prob, Riccati())
save_to_hdf5("gpec.h5", ffs)

solve returns its result without writing a file. Call save_to_hdf5(path, ffs) or pass an open HDF5 file or group to save it explicitly.

The same save_to_hdf5(target, result) function saves an equilibrium, local-stability result, perturbed-equilibrium state, kinetic-force state, tearing result, or error-field result. Each module owns the datasets for its result. Paths open or create an HDF5 file; an open file or group remains owned by the caller. Stage computations return results without writing anything. Each save also records, in Input/gpec_toml_raw, the deck sections stating the problem, algorithm and controls the result was computed with, so a script run's file replays like a deck run's: main(["gpec.h5"]). A forcing no deck can state (a weighted field, a spectrum or a sum) is replayed from the control-surface modes the save records.

A deck runs through these same calls. main translates each section of gpec.toml into the problem, algorithm or control it names, calls the function above for every section present, and saves each result into the one [Run] output_file, so a deck can never take a path a script cannot. It returns (; equil, local_stability, ffs, match, resp, pe, kinetic, error_fields, tearing), each nothing when its section is absent; ffs is the result the later stages read (matched when the deck has [Match]) and match its MatchResult.

The objects map one-to-one onto the pipeline stages:

  • PlasmaEquilibrium reads and processes the equilibrium — the [Equilibrium] section. Analytic equilibria take their parameters from their config object, with the eq_type implied, and IMAS equilibria from a data dictionary:

    eq = PlasmaEquilibrium(Equilibrium.SolovevConfig(; elongation=1.5); mpsi=0)
eq = PlasmaEquilibrium(dd; imas_cocos=11)

    Every equilibrium remembers its source, so with mpsi=0 solve re-forms it on the same refined two-pass grid the deck uses; Equilibrium.reform(eq, psi_nodes) re-forms it on any grid.

  • solve runs the force-free-states stage — the [ForceFreeStates] section — and returns a ForceFreeStatesResult, exactly the object the TOML driver publishes.

  • RMPField describes the external field — the [ForcingTerms] section — without reading anything from disk until it is applied.

  • plasma_response builds the plasma-response and singular-coupling operators of a ForceFreeStatesResult once, and perturbed_equilibrium(resp, rmp) drives them with one field — together the [PerturbedEquilibrium] section.

  • kinetic_torque evaluates the kinetic (NTV) torque of a perturbed equilibrium with the model settings of a KineticForcesControl — the [KineticForces] section — and returns a KineticForcesResult: kf = kinetic_torque(pe, KineticForcesControl()).

  • error_fields assesses the error field of a set of coils on a plasma response — the [ErrorFields] section — and returns an ErrorFieldsResult: ef = error_fields(resp, pe.coil_sets, ForcingTerms.CoilConfig(ft_ctrl); tolerances).

Kinetic profiles

The equilibrium carries the kinetic profiles. Name the file with the kinetic_file (and, for HDF5, kinetic_group) keyword, the same keys as the [Equilibrium] deck section, and it is read once into equil.kinetic; every kinetic stage derives its own view from it. Equilibrium.attach_kinetic_profiles! attaches a file or in-memory KineticProfileData to an equilibrium built without one, such as an analytic equilibrium.

eq = PlasmaEquilibrium("input.geqdsk"; jac_type="hamada", kinetic_file="kinetic.h5")

Combining forcing sources

RMPFields form a vector space: +, - and scalar * build lazy linear combinations that record their terms and compute nothing until the perturbed-equilibrium stage materializes them. Because the plasma response is linear in the forcing, driving with a combination is exactly equivalent to combining the individually materialized fields — each term is evaluated on the control surface and the mode amplitudes are summed. A complex scalar phase-rotates a source.

nominal    = RMPField("nominal_efc.dat")
weld_field = RMPField("weld_fields.h5")
pe = perturbed_equilibrium(resp, 2.0 * nominal + 0.5 * weld_field)

This is the substrate for error-field workflows: build per-unit sources independently (a coil set per ampere, a displacement field per millimeter), then assemble physical cases by weighting and summing — without recomputing anything per combination until the final perturbed_equilibrium call, and with one plasma_response serving every combination. RMPField(modes) wraps a control-surface spectrum computed elsewhere, already in the unit-norm Φ_x convention, as a leaf that combines like any other.

The weights are linear-combination coefficients, not physical amplitudes: sources that are not scalar multiples of each other get their own description and the algebra. A coil set with a failed conductor is nominal - failed_coil, not 0.9 * nominal.

Choosing an integrator

The second argument of solve picks the formalism, and its fields are that formalism's numerical settings. Physical inputs belong on ForceBalanceProblem; ODE tolerances and storage settings belong on Forward or Riccati, and extended_precision_bvp belongs only on Riccati. The current deck reader translates its existing section layout into those objects:

ffs = solve(eq, Forward(; eulerlagrange_tolerance=1e-8); nn=1, vac_flag=true) # dense ξ profiles for PerturbedEquilibrium
ffs = solve(eq, Riccati(; nchunks=40); nn=1, vac_flag=true)     # chunked propagators, Δ′ matrix
ffs = solve(eq, Galerkin(; nx=512); nn=1)                       # RDCON outer-region Galerkin Δ′

Which products each formalism can supply differs; a result carries nothing in the fields its integrator does not produce and consumers warn and skip rather than erroring. See the Stability Analysis page for the result struct and its capability gates.

singfac_min, frobenius_order, frobenius_psi_max, truncate_at_dW_peak, and dW_edge_scan_start remain problem settings. Galerkin rejects non-default values of the last three. Its per-surface order adjustment is controlled by frobenius_order_ceiling, and its factorization is selected automatically.

Inner-layer matching

Inner-layer matching is its own problem, posed on a finished solve: a MatchProblem holds the outer Δ′ the solve published plus the per-surface layer parameters, and the inner-layer model passed to solve computes the layer response at the prescribed rotation. Solving it returns a new result with the closure changed from :ideal to :matched and the eigenfunctions replaced — the expensive outer solve is reused, so layer-parameter scans cost one cheap match solve per point:

ffs = solve(eq, Galerkin(; rpec_flag=true, cut_solution=true); nn=1)

matched = solve(MatchProblem(ffs; eta=1e-6, rho=1e-7, rotation=0.0), GGJModel())
@assert matched.closure === :matched

# A rotation scan reuses the one outer solve:
bpens = [solve(MatchProblem(ffs; eta=1e-6, rho=1e-7, rotation=f), GGJModel()).bpen for f in 0.0:50.0:500.0]

A scalar applies to every surface; a vector gives one value per entry of ffs.surfaces, core to edge. The problem needs a Δ′ payload with coil-response columns, so it accepts Galerkin (rpec_flag=true) and Riccati (vac_flag=true) results; a Riccati-fed match fills bpen and the resonant data but keeps solution === nothing (no outer basis is retained). Only a closure-capable model is accepted — GGJModel() today; SLAYERModel() is slab-only and drives the free-eigenvalue tearing solve instead.

A deck poses the match with a [Match] section (eta, rho, rotation, gamma, ideal, inner_model = "GGJ"), and [GGJ] holds the GGJModel keywords (solver and its options).

Tearing stability

A TearingProblem holds the outer solution and the surface coupling. The plasma is the equilibrium's kinetic data (profiles, species, transport defaults, resistivity closure), the inner-layer model holds its own closures, and TearingConfig holds the scan and root-search settings.

tear = solve(TearingProblem(ffs), SLAYERModel(; P_perp_model=:chi_perp_e);
    config=TearingConfig(; Q_re_range=(-2.0, 2.0), Q_im_range=(-0.5, 3.0)))
ggj = solve(TearingProblem(ffs; coupling_mode=:coupled), GGJModel(; solver=:ray);
    config=TearingConfig(; gamma_range=(1.0, 1e4), omega_range=(-1e4, 1e4)))
save_to_hdf5("gpec.h5", tear)

GGJ needs the raw Δ′ matrix and validates the surface ordering. Its η and ρ default from the kinetic data: η by the resistivity closure SLAYER uses, ρ = mi·ni of the main ion; pass eta and rho to TearingProblem to override them. Both models report lab-frame frequencies with per-surface E×B shifts: a coupled solve evaluates each layer in its own E×B frame (GGJ's sk = s + i·n·ΩE, Johnson & Greene 1967 Appendix B), and an uncoupled root is moved from its layer's frame by n·ΩE. ΩE comes from the kinetic data's omega_E, or from omega_E_kHz for the m/n it lists. Both expose omega in rad/s and gamma in 1/s, positive for instability, and the HDF5 roots group records frequency_frame. SLAYER searches a normalized Q box, GGJ a physical (γ, ω) box.

A deck runs the solve with a [Tearing] section: the TearingProblem keywords and inner_model = "SLAYER" or "GGJ", with [Tearing.search] for the TearingConfig keys and [Tearing.CriticalResonantField] for the penetration threshold. The model's keywords sit in [SLAYER] or [GGJ]; [SLAYER] also gives the layer-overlap cap its closures.

Kinetic runs take Forward(). The problem's kinetic keyword selects the source: kinetic=KineticForcesControl(; ...) evaluates the KineticForces drift-kinetic matrices with those settings on the equilibrium's kinetic profiles and species, and kinetic=TestKineticMatrices(; scale) uses synthetic test matrices. kinetic_factor (default 1) scales either. km = kinetic_matrices(prob) evaluates the source once, and kinetic=km reuses those KineticMatrices in later solves, for example a kinetic_factor scan. A deck selects the KineticForces model with [ForceFreeStates] kinetic = "KineticForces", using its [KineticForces] section.

Local stability

The Mercier, resistive interchange and ballooning profiles are their own stage, posed on the equilibrium. A LocalStabilityProblem holds the equilibrium, ballooning angle theta_k, and alpha_boundary_scan choice. Ballooning holds numerical tolerances and scan settings. solve returns a LocalStabilityResult; its verbose keyword defaults to false. A deck states the problem in [LocalStability] and the numerics in [Ballooning].

problem = LocalStabilityProblem(eq; theta_k=0.0, alpha_boundary_scan=true)
ls = solve(problem, Ballooning(; n_scan=64); verbose=false)
ls.psi, ls.D_I, ls.D_R, ls.ballooning_Delta_prime     # profiles on the equilibrium ψ grid
ls.ballooning_psi, ls.alpha, ls.alpha_critical        # first ballooning boundary, NaN outside its scan window

Entry points

GeneralizedPerturbedEquilibrium.ForceBalanceProblem — Type
ForceBalanceProblem(equil; nn, wall=nothing, kwargs...)

The perturbed force-balance problem posed on an equilibrium, whose solutions are the force-free (or, with a kinetic source, kinetic) perturbed states. With kinetic terms the force operator is not self-adjoint, so this is not always an energy extremization. The integrator passed to solve sets the numerics; inner-layer matching is a separate MatchProblem on the finished solve.

nn is the toroidal mode number or range and wall the vacuum wall shape. Remaining keywords describe physics and workflow controls; numerical settings belong on the integrator passed to solve. nn_low/nn_high are rejected — they come from nn.

Fields

  • equil::Equilibrium.PlasmaEquilibrium - The equilibrium the problem is posed on.
  • wall::Union{Nothing,Vacuum.WallSettings} - Vacuum wall shape for the free-boundary energies.
  • ctrl_kwargs::Dict{Symbol,Any} - ForceFreeStatesControl keywords, nn already folded in.
source
CommonSolve.solve — Function
solve(prob::ForceBalanceProblem, alg; verbose=false) -> ForceFreeStatesResult
solve(equil, alg; nn, verbose=false, kwargs...) -> ForceFreeStatesResult

Solve the perturbed-plasma ForceBalanceProblem with the formalism alg — Forward, Riccati or Galerkin — and return the published ForceFreeStatesResult. This is the scripting entry point; it runs the same stages a gpec.toml run of main does and produces the same result object. The second form is sugar building the problem from an equilibrium and the problem keywords in one call.

Knobs owned by alg are rejected as ForceFreeStatesControl keywords. Kinetic runs (a kinetic source) take Forward(). kinetic=KineticForcesControl(; ...) evaluates the KineticForces model with those settings on the equilibrium's kinetic profiles (kinetic_file, or attach_kinetic_profiles!); kinetic=TestKineticMatrices(; scale) uses synthetic test matrices; kinetic=km reuses the KineticMatrices from kinetic_matrices.

eq = PlasmaEquilibrium("input.geqdsk"; jac_type="hamada")
prob = ForceBalanceProblem(eq; nn=1, delta_mlow=8, delta_mhigh=8, vac_flag=true)
ffs = solve(prob, Riccati())
ffs = solve(eq, Riccati(); nn=1, vac_flag=true)   # equivalent one-line form
source
solve(equil::PlasmaEquilibrium, alg; nn, verbose=false, kwargs...) -> ForceFreeStatesResult

Convenience form of solve: builds the ForceBalanceProblem from the equilibrium and the problem keywords, then solves it with alg.

source
solve(prob::TearingProblem, model) -> TearingResult

Tearing growth rates per surface with the inner layer of model.

source
solve(prob::MatchProblem, model) -> ForceFreeStatesResult

Match prob.ffs to the inner layer of model. The result has closure = :matched (:ideal with ideal=true), bpen, the MatchResult in result.match and, for a Galerkin solve, the matched ξ. A :matched result drops the ideal δW (wp, free_boundary), so PerturbedEquilibrium skips its response rather than mixing ideal and matched physics.

source
GeneralizedPerturbedEquilibrium.kinetic_matrices — Function
kinetic_matrices(prob::ForceBalanceProblem, alg=Forward(); verbose=false) -> KineticMatrices

Evaluate the kinetic matrices of prob's kinetic source once, running the part of solve before the Euler-Lagrange integration. Pass them back as the problem's kinetic to solve without evaluating them again: the solve is identical to one with the source itself, and may change kinetic_factor.

km = kinetic_matrices(ForceBalanceProblem(eq; nn=1, kinetic=KineticForcesControl()))
scan = [solve(ForceBalanceProblem(eq; nn=1, kinetic=km, kinetic_factor=f), Forward()) for f in (0.5, 1.0, 2.0)]
source
GeneralizedPerturbedEquilibrium.PerturbedEquilibrium.perturbed_equilibrium — Function
perturbed_equilibrium(resp, rmp; regularization_width=0.0, verbose=false, coil_sets=nothing)
    -> PerturbedEquilibriumState

Drive the plasma response resp (from plasma_response) with the external field rmp, an RMPField, and return the perturbed-equilibrium result. One response serves any number of fields, so a scan rebuilds no operator.

regularization_width smooths the ideal 1/(m−nq) divergence in the profile reconstruction (Fortran reg_spot); its default is 0, and 0.05 is typical for driving KineticForces with an ideal solve. Call save_to_hdf5(target, pe) to save the result. coil_sets injects already-built coil geometry (the gpec.h5 replay path), bypassing the geometry read.

resp = plasma_response(ffs)
pe = perturbed_equilibrium(resp, RMPField("forcing.dat"))
source

plasma_response, which builds the PlasmaResponse that perturbed_equilibrium applies, is documented with the perturbed equilibrium module.

Integrator selectors

GeneralizedPerturbedEquilibrium.ForceFreeStates.AbstractIntegrator — Type
AbstractIntegrator

Numerical algorithms for the force-balance problem. Physical inputs remain on the problem; each integrator carries its own accuracy, storage, and discretization settings.

source
GeneralizedPerturbedEquilibrium.ForceFreeStates.Forward — Type
Forward(; kwargs...)

Serial forward integration with Gaussian reduction and dense solution profiles.

Fields

  • eulerlagrange_tolerance::Float64 - Relative tolerance for ODE integration.
  • renorm_threshold::Float64 - Column-norm growth threshold for Gaussian reduction or Riccati renormalization.
  • numsteps_init::Int - Initial capacity for stored ODE solution steps.
  • numunorms_init::Int - Initial capacity for solution-normalization records.
  • save_interval::Int - Save every Nth ODE step; always retain steps near rational surfaces.
  • nchunks::Int - Target chunk count; zero derives the count from the singular surfaces.
source
GeneralizedPerturbedEquilibrium.ForceFreeStates.Galerkin — Type
Galerkin(; nx=256, ...)

RDCON outer-region singular Galerkin solver: solves the same Euler-Lagrange system variationally on a finite-element grid packed around the rational surfaces, producing Δ′ without a radial ODE sweep. Maps onto integrator = "Galerkin"; every field is the corresponding discretization setting. Factorization is selected automatically.

Fields

  • nx::Int - Elements per interval between singular surfaces.
  • nq::Int - Gauss-Lobatto quadrature order per element.
  • pfac::Float64 - Grid packing ratio near singular surfaces.
  • dx0::Float64 - Resonant-element integration truncation distance, in units of 1/|n q′|.
  • dx1::Float64 - Resonant-element size, in units of 1/|n q′|.
  • dx2::Float64 - Extension-element size, in units of 1/|n q′|.
  • cutoff::Int - Number of elements carrying the large solution as driving term.
  • tol::Float64 - Resonant-quadrature tolerance.
  • gnstep::Int - Maximum resonant-quadrature evaluations.
  • dx1dx2_flag::Bool - Enable the special dx1/dx2 treatment of resonant and extension elements.
  • frobenius_order_ceiling::Bool - Auto-raise the order per surface for a high Mercier index.
  • rpec_flag::Bool - Append the mpert coil-response columns to the Δ′ solve. Required for a later MatchProblem solve on the result.
  • edge_onesided::Bool - Pack the two end intervals one-sided toward their single rational end instead of the Fortran symmetric pack.
  • basis_output::Bool - Save the raw Galerkin basis for development diagnostics.
  • cut_solution::Bool - Also keep the cut solution, for a later MatchProblem's composite inner profiles.
source
GeneralizedPerturbedEquilibrium.ForceFreeStates.Riccati — Type
Riccati(; kwargs...)

Chunked Riccati integration and the singular-surface boundary-value solve.

Fields

  • eulerlagrange_tolerance::Float64 - Relative tolerance for ODE integration.
  • renorm_threshold::Float64 - Column-norm growth threshold for Gaussian reduction or Riccati renormalization.
  • numsteps_init::Int - Initial capacity for stored ODE solution steps.
  • numunorms_init::Int - Initial capacity for solution-normalization records.
  • save_interval::Int - Save every Nth ODE step; always retain steps near rational surfaces.
  • nchunks::Int - Target chunk count; zero derives the count from the singular surfaces.
  • extended_precision_bvp::Bool - Use Complex{Double64} for the Delta-prime BVP and PEST3 combination to reduce cancellation error.
